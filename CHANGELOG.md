# Development changelog

This log distinguishes code installed locally from GitHub releases. It summarizes completed work; `docs/architecture.md` holds the detailed verification record, and `PENDING_CHANGES.md` holds unfinished work.

## Local development bundle after v1.68 — not yet published

- **Mixed Instagram album transfer (unverified on phone):** Ordered photo/video carousel children now share one album job. Photos retain the existing quality selection; each video reuses the muxed MP4, audio-sample, metadata, and MediaStore path, with its own filename, saved-file identity, thumbnail, codec details, Open action, and retry slot. Legacy photo records default to photo when the new item kind is absent. A synthetic photo-video-photo embed parser probe and a legacy/mixed history JSON round-trip probe passed, along with the Java suite and signed build. A real mixed carousel, network transfer, saved media, notification, and UI remain untested; this is unreleased development code and was not installed on the phone.
- **Mixed Instagram album groundwork:** The resolver now keeps an ordered item plan for photo and video children, including candidate streams for each video. The transfer explicitly stops mixed albums before saving new items, so it cannot silently produce an incomplete photo-only album. A model test covers mixed order, legacy photo-only results, and invalid order; the Java suite and signed build passed. Mixed-item transfer, retry, Downloads-page details, and live verification remain pending. No phone interaction or release occurred for this slice.
- **Story strip detection refinement:** The Instagram collector now scans a wider top-screen band and requires tighter spacing between segment centers. Offline replay of four recorded Story frames selected the actual two- or four-segment strip and rejected a five-part image edge above it. The Java suite and signed build passed, and the APK installed without launching a source app. A different screen ratio and a fresh live Story scan remain pending.
- **Instagram account Story collection:** Added a one-tap collector that reads the visible segment strip, copies fresh Story links, rejects other accounts and linked posts, and queues only a complete distinct set. On the HMD Skyline, it collected four links for one visible account and two for another while closing the share sheet between segments; the Downloads page showed separate Story jobs with source links and Retry. All six anonymous media lookups failed before a file was saved, so full-resolution video/photo output is still pending. The Java suite and signed build passed, and the development APK installed locally. No release was published.
- **Floating button feedback:** The overlay arrow now shrinks and dims on press, then returns to its saved size and opacity. On the HMD Skyline, screen recordings showed the effect with the existing transparent built-in icon and an imported transparent PNG. A short TikTok tap still copied a fresh link, kept TikTok in front, and completed a 1.6 MB video download. The test icon was removed and the previous solid icon and 53 dp size were restored. The Java tests and signed build passed; this remains in the unreleased bundle.
- **Source-app audit:** On Instagram 450.0.0.50.77, two live Story accounts and two opened Reels yielded valid current share links but no anonymous media data. The Story profile pages lacked the owner ID; the tested Reel's Reel, post, and embed routes returned application shells without video variants. The same Reel failed with Thunder VPN temporarily off, after which the prior United Kingdom VPN location was restored. No other post or preview was saved in their place. RedNote 9.44.0's Following circles led to a dated “Frequently viewed” author feed, and its inspected profile had Notes/Saves/Likes rather than a Story viewer; the feature catalog now scopes RedNote Stories to a future observable viewer.
- **RedNote live-video and album matrix:** Two newly visible RedNote feed videos downloaded from the floating button on the HMD Skyline. The 29,135,550-byte MP4 was 1080×1920 H.265/Dolby Vision with AAC; the 15,691,163-byte MP4 was 1012×1876 H.265 with AAC. Pulled files matched the phone SHA-256 hashes, FFmpeg decoded video and audio samples, and sampled frames showed no RedNote or creator overlay. Their embedded Comment fields contained the sanitized public post permalink. A fresh four-photo post saved all four ordered JPEGs at listed dimensions. Its missing fourth photo was restored twice with its original SHA-256: first by tapping the floating button again, then by the card's direct Redownload action. Both retries reused the existing card, retained the other three photos, and left no temporary backup. RedNote retries now preserve and prefer a validated short share link; a newly copied short link can refresh a legacy failed card only after the returned post ID matches. Older records without a working link remain pending.
- **Unreleased cross-app album recovery verification:** On the HMD Skyline, a three-photo RedNote album lost access to its first 4284×5712 HEIC. Selecting the exact saved file through Android's picker returned the card to 3 of 3 Complete. A two-photo Instagram album similarly returned to 2 of 2 Complete after selecting its missing JPEG; the picker rejected a different same-size filename. Both originals and the untouched photos retained their SHA-256 hashes, and temporary test backups were removed. Explicit Redownload of the Instagram missing photo was previously blocked by another complete card for the same post; it now starts for a recorded missing file, while active transfers still take priority in duplicate checks. Instagram then withheld public media details. The older RedNote album's recorded canonical link redirected to an unsupported path; the fresh-album test above verified the repaired short-link retry path.
- **Unreleased album recovery fix:** A missing TikTok album photo was detected while the other photo stayed intact. The first retry timed out and exposed a bug that erased the missing photo's expected byte size. Retry now retains that size. An affected JPEG record can be relinked through Android's picker only when its filename, decoded dimensions, and embedded public post link match. On the HMD Skyline, relinking restored a complete 2-of-2 album and Open photo launched Photos. A second Redownload saved the missing photo with the original SHA-256; the other photo's SHA-256 was unchanged. Both saved files are present, and the temporary test backup was removed.
- **1.80:** Placed the search-field X at the far right and Paste immediately to its left. On the HMD Skyline, Paste filtered 441 records to 20 RedNote matches and X restored the full list. The Java tests and signed build passed.
- **1.77–1.79:** Indexed history off the UI thread; added full-history search, 15 records per page, Newer/Older controls at the top and bottom, notification focus on the correct page, a Paste action, and saved-file relinking through Android's picker. The phone rendered 441 records by page and restored a selected MP4 after reinstall. Album-photo relinking was verified later in this bundle.
- **1.75–1.76:** Blocked repeat transfers for the same post and validated saved-file identity using both filename and actual byte size. Added Redownload when a saved file is missing or changed. A TikTok duplicate and a deleted-video redownload passed on the phone. Missing-photo recovery was verified later in this bundle.
- **1.74:** Added the dark Downloads and Settings theme. Phone screenshots confirmed the cards, controls, dialog, and live button preview.
- **1.73:** Added Retry download on failed cards, reusing the existing record and notification identity. A failed TikTok download completed on retry as a 1080×1920 H.265/AAC MP4.
- **1.72:** Added system, HTTP proxy, and SOCKS route settings and Android-managed IKEv2 profile controls. Public HTTP and SOCKS test routes downloaded a TikTok MP4 with audio on the phone. VPN profile provisioning and tunnel connection remain untested.
- **1.71:** Added a wall-clock deadline and one exact-post retry for transient TikTok page transport failures. Two formerly failing links completed as muxed MP4s on the phone.
- **1.69–1.70:** Added Android Share-menu intake without Accessibility and minimized inspection of unrelated apps' window content. Share-to-download completed on the phone with Accessibility disabled. Arab Bank still rejected the enabled Accessibility service when it was restored.
