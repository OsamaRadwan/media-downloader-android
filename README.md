# Media Downloader

**Downloads:** [All versions and release notes](https://osamaradwan.github.io/media-downloader-android/) · [Latest APK](https://github.com/OsamaRadwan/media-downloader-android/releases/latest) · [Source repository](https://github.com/OsamaRadwan/media-downloader-android)

The project lives in `D:\Apps\MediaDownloader`. The Java source, tests, and Android application ID use `com.codex.mediadownloader`. TikTok and Instagram are supported sources. This package ID creates a separate Android installation from the earlier prototype; its private settings, download history, and Accessibility permission did not transfer automatically. Previously saved files remain in the phone's Downloads collection.

An Android app that shows a configurable download arrow over TikTok and Instagram. Tap the floating arrow to download the current video or all photos in a public photo album; long press it to open Media Downloader's Downloads page. Its Accessibility service uses the current post's Share → Copy link controls and waits for a fresh clipboard result. A foreground service then downloads listed media directly to Downloads. For video, it requires one MP4 with both video and audio. Up to three download jobs can run at once.

Instagram feed posts and opened Reels have separate saved button positions. The Settings page can preview each position at the screen border. The Instagram resolver reads public embed data without the installed Instagram app's cookies, downloads each listed photo rendition to choose the largest actual image, and validates MP4 tracks before saving. When a single-photo embed omits structured media, it checks the main image's cache key against the requested post ID and compares the responsive renditions. On the connected phone, two single photos saved at 1439×1455 and 1440×1440, a two-photo NASA album saved both images at Instagram's listed 1000×1249, and a feed video and opened Reel saved 720×1280 MP4s with AAC audio. One Reel supplied only a video-only MP4 and failed visibly. These are the largest accessible renditions observed for those posts, not a guarantee of original upload resolution. A VPN changed Instagram's public response during earlier testing.

Stories: TikTok Story links that resolve to video or photo post IDs use the same stream and image quality checks as posts. Instagram Story taps copy the individual Story URL and attempt a separate anonymous Story lookup; a public NASA Story returned no media from that endpoint on the test phone, so it failed visibly. The app does not substitute the shared post shown inside a Story or a screen capture. Full-resolution Story saving therefore depends on the source exposing an accessible media rendition. See `FEATURES.md` for the exact supported paths and limits.

The app has **Downloads** and **Settings** tabs. Downloads shows current progress, speed, size, thumbnail, file details, failures, and earlier completed files. Tapping a progress or result notification opens that download in the Downloads tab. A download entry links to its source post in TikTok or Instagram. Every completed video entry has a compact **Open video** button that stays visible with details collapsed, plus a tappable thumbnail; both open its saved MP4 in a video player. Settings shows the download button at its live screen-border position and has a larger centered preview. It offers solid, outline, simple, and tray download icons and lets you add up to 30 custom images from the phone. Imported images need transparent pixels, are copied into app-private storage, and can be selected or removed later. Built-in icons use the arrow color control; custom images keep their own colors. Position, size, padding, background, and opacity controls apply to either type, and changes save automatically.

The app needs Accessibility, display-over-other-apps, and notification access. Notification channels are silent. It resolves public post data with a fresh anonymous web session, separate from the signed-in TikTok app. Video and photo transfers first request each listed media address without visitor cookies; an access rejection may retry with that download job's anonymous visitor cookies. Rate limits do not trigger a cookie retry. It ranks the playback formats TikTok lists, tries the highest eligible resolution first, and verifies the saved MP4's actual dimensions and audio track. Each new MP4 embeds its TikTok post URL in Comment, available post title in Title, full caption in Description, and hashtags in Keywords before saving. TikTok's stream servers can reject individual URLs; a failed download remains visible with the server error. The app does not use TikTok's Save video action. A video's original upload resolution may be higher than the playback formats TikTok exposes to this app.

Settings also has an **Export diagnostic report** button. The app keeps separate dated failure and operation logs for the current UTC day and six prior days, with per-day limits of 512 KiB and 256 KiB respectively. The report adds recent failed-job details, validated public post links without tracking queries, HTTP outcomes, app and source-app versions, Android build, network, display, storage, permissions, and button settings. Cleanup runs inside the app at startup, at a day change while it runs, and on log access; it uses no Android alarm. The app does not automatically send the report or read system logcat. The v1.52 export flow was verified on an HMD Skyline running Android 15.

For photo posts, the app reads the complete ordered image list in the post data and saves each image to public Downloads. It checks desktop, 4096-pixel wide desktop, and mobile page responses for distinct signed renditions of each photo, then compares the actual decoded resolution of every discovered image address and keeps the largest accessible file. Album cards show progress, per-photo details and thumbnails, whether new files match TikTok's listed dimensions, Open photo actions, and Retry missing photos after a partial failure. JPEG files embed the source URL and available post text in EXIF metadata; the app record keeps that metadata for every image format. TikTok may not expose the original upload resolution.

New files use `<profile name>_profile_<account ID>_VideoID_<video ID>_<yyyy-MM-dd_hh-mm>.mp4`, using the video's publish time. Existing files from older versions remain in the phone's Downloads folder. The new app starts with its own appearance preferences and download history.

Build with `./build.ps1` from PowerShell. It uses the Android SDK in `D:\Random\AndroidSdk` and produces `MediaDownloader.apk`. Run the pure architecture checks with `./test.ps1`. The reusable feature catalog is in `FEATURES.md`; architecture decisions and future-update instructions are in `docs/architecture.md` and `AGENTS.md`. The historical prototype is stored outside the active project.

The [release checklist](docs/releasing.md) describes version tags, APK checksums, and publishing future versions. The download page lists published GitHub Releases automatically.
