# Media Downloader v1.59 — clean RedNote video stream

**Device test status: NOT TESTED on the phone.** The connected phone disappeared from ADB during this work. The APK builds and the RedNote source path was tested against a live public video from a separate share link.

## Changes

- RedNote video downloads try the public original-upload asset before web playback streams. That request omits the post Referer, which blocked the original CDN asset in the observed test.
- The resolver rejects known stamped RedNote playback types `259` and `309`. It accepts only an original asset or a playback type identified as clean; if no such stream with both video and audio is accessible, the job fails instead of saving a video with a platform or account overlay.
- Current `media.stream` and `mediaV2` stream lists are checked. Filename, metadata, download history, progress notifications, and settings remain compatible.

## Verification

- A live public RedNote video exposed a 720×1280 type-259 stream and a separate original asset. The downloaded type-259 frame visibly contained RedNote branding and the account label. The original was 2160×3840 H.264 with AAC audio, 104,519,957 bytes; sampled frames at 2, 10, and 17 seconds had no platform or account overlay.
- The production resolver selected the original as its only candidate for that post. An anonymous range request for the original succeeded without a Referer and was refused with a post Referer.
- The 2160×3840 original passed the app's MP4 metadata writer; an independent media probe still found its H.264 video and AAC audio afterward.
- All nine local Java test groups passed. The APK compiled, passed signature verification, and reports package `com.codex.mediadownloader` versionCode 60/versionName 1.59.

An account name or other text intentionally placed in the creator's original upload remains part of that picture. Existing downloaded videos are not modified by this release.
