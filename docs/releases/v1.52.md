# Media Downloader v1.52 — seven-day diagnostics

**Device test status: VERIFIED for the diagnostics flow.** Version 1.52 was installed over v1.51 on an HMD Skyline running Android 15. Settings exported a report to Downloads through Android's document picker. The report contained app and source-app versions, Android/network/button context, recent job details, sanitized public source links, failure events, and new dated operation events. No cookie fields or signed CDN links appeared in that report. The Accessibility service was restored after the test's ADB force-stop and confirmed enabled. Eight local Java tests passed, including seven-day pruning and dated-file isolation. A fresh media transfer was not repeated for this diagnostics release.

## Changes

- Keeps the current UTC day and six prior days of diagnostic events, deleting the oldest day's entries on day eight. Cleanup runs inside the app at startup, at a UTC day change while its process runs, and when logs are accessed. There is no Android alarm or external cleanup process.
- Maintains separate dated failure and operation logs, so activity on a later day cannot rotate away an earlier day's file. The daily limits are 512 KiB and 256 KiB respectively; a capacity marker reports omitted events if either limit is reached. The operation trace includes the job, stage, media request mode, sanitized host, HTTP status, response type and size, elapsed time, and selected media dimensions where available.
- Exported reports include recent failed/partial/active job details and validated public source links without query strings, plus app and source-app versions, Android build, network, display, storage, permission, and button-settings context. This aims to make reports useful for remote investigation without connecting the affected phone.
- Diagnostic events continue to redact signed URLs, file paths, long IDs, and common secret values. Reports are shared only when the user chooses a destination.

Cleanup is an in-process check. If Android stops the app process, physical deletion occurs the next time the app starts or accesses logs. A busy day that reaches its size limit retains its existing entries and adds a capacity marker; subsequent events that day are omitted. The earlier public media transfer changes remain unverified on this phone, so this version is published as a prerelease.
